## 测评场景汇总

### 1. 入门：提示词基础用法

刚开始用 AI，掌握三件事就够了：

**结论：** 说清楚你要什么 + 给足背景信息 + 指定输出格式。这三点能解决 80% 的"AI 没答到点上"问题。

**示例对比：**

❌ 效果差：
```
帮我写一篇文章
```

✅ 效果好：
```
你是一名科技媒体编辑，帮我写一篇面向普通用户的 AI 科普文章，
主题是"什么是 Token"，字数 800 字左右，语气轻松，
结尾加一个实用小技巧。
```

---

### 2. 进阶：结构化提示词（LangGPT 方法）

**结论：** 如果你只学一个进阶技巧，推荐结构化提示词。最典型的是 **LangGPT 方法**，把一条提示词拆成几个模块：

```
# 角色
你是一名资深的 Java 后端工程师

# 背景
我正在开发一个 Spring Boot 项目，需要接入 Claude API

# 任务
帮我写一个 Service 层的代码，实现流式调用 Claude 的功能

# 要求
- 使用 WebClient 实现 SSE 流式输出
- 加上错误处理和超时设置
- 代码注释用中文

# 输出格式
直接给出完整可运行的代码，不需要解释
```

这种写法的好处：条理清晰，AI 不容易理解偏，输出质量稳定，而且可以复用。

---

### 3. 高级技巧：多轮迭代 + 追问

**结论：** 很多高手的秘诀不是提示词写得多精妙，而是**特别会追问**。不要指望一次就得到完美答案，第一次给方向，后面几轮不断精炼。

常用追问模板：
- "你刚才说的 X 部分，能更详细展开吗？"
- "这个方案有什么潜在问题？"
- "换一种风格/方式再来一版"
- "假设我是完全不懂技术的用户，怎么解释这件事？"

## 原文总结

AI 学习没有捷径，但有节奏：**先把提示词基础用顺 → 再学结构化写法 → 然后练追问迭代的习惯 → 最后找到自己信任的信息源保持更新**。

工具会变，模型会更新，但"说清楚需求、不断迭代"这个底层逻辑不会过时。
