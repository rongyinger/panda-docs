## 关键认知：你看到的 ≠ 模型处理的

用户发了一句"帮我写段代码"，但模型实际处理的内容远不止这句话。

**每次调用实际消耗的 Token 包括：**

```
系统 Prompt（每次都计费）
  +
全部历史消息（第1轮到现在）
  +
本次用户输入
  +
模型输出内容
  +
Tool Call 内容（如有）
= 实际计费 Token
```

## 典型翻倍场景

**场景一：长系统 Prompt**
有些客户端预置了几千字的系统提示词，每次对话都带上，你完全没感知。

**场景二：全量历史消息**
聊了 50 轮的对话，第 51 轮发送时，前 50 轮全部打包发给模型，Token 是累加的。

**场景三：图片输入**
一张 1080p 图片约等于 1000-2000 个文本 Token，分辨率越高越贵。

**场景四：工具调用**
Function Calling 的 schema 定义和工具返回结果都计入 Token。

## 降低消耗的方法

- 定期开新对话，不要在一个对话里聊几十轮
- 缩短或简化系统 Prompt
- 压缩图片分辨率后再上传
- 选用轻量模型处理简单任务（DeepSeek、Claude Haiku）
- 使用 Prompt Caching（适合固定系统 Prompt 的场景）
