Claude Code 省 Token 实战：7 个技巧把成本砍掉一半 ​

本文整理自多位开发者的实战经验，综合以下来源：

  • Claude Code Token 收费估算 · 博客园
  • 7 个实用技巧，让 Claude Code 的 Token 消耗暴降 80% · SegmentFault
  • Claude Code 太烧钱了？5 招把 token 成本砍了一半 · 知乎
  • CC Academy 省钱秘笈

原文观点仅代表作者个人意见。

前言 ​

很多人用 Claude Code 都有过这种困惑：明明只写了几个小功能，Token 就没了；一天随随便便花了几十美元，甚至怀疑"比请个实习生还贵"。

其实 Token 烧得快，根源只有一个：上下文在悄悄膨胀。每一轮对话，Claude 都要把之前所有的历史记录重新读一遍，历史越长，每条消息就越贵。本文整理了 7 个立竿见影的技巧，帮你把成本控制在合理范围内。

一、先搞清楚钱花在哪了 ​

一次典型的 Claude Code 开发会话，Token 构成大概是这样：

消耗来源占比
对话历史累积53%
读取的源文件20%
AI 响应内容20%
系统提示 / CLAUDE.md3%
工具调用（Bash / 编辑器）4%

关键结论：超过一半的 Token 花在了"对话历史"上，而不是你真正提的问题。这是最值得优化的地方。

二、7 个省钱技巧 ​

技巧 1：用 /compact 压缩上下文（节省 80%+） ​

/compact 会把之前的对话历史从 25000 Token 压缩成约 3000 Token 的摘要，节省率超过 80%。

什么时候用：

  • 对话超过 5 轮
  • 完成一个子任务、准备开始下一个
  • 感觉 Claude 响应变慢了（上下文太长会拖慢速度）

还可以带参数，告诉它重点保留什么：

/compact 保留所有代码修改记录和文件路径，丢弃分析过程
1

⚠️ /compact 是有损压缩，细节可能丢失，适合"换挡"时使用。

技巧 2：用 /clear 彻底清空（任务切换必做） ​

完全切换任务时用 /clear，比如从项目 A 切到项目 B，或者从写功能切到修 Bug。不要把上一个任务的上下文带进新任务，这是最容易被忽视的浪费。

推荐习惯：把 /clear 当成 Git commit 一样，完成一个功能点就清理一次。

技巧 3：精准描述需求，别让 Claude 自己去找 ​

❌ 低效写法：

登录有问题，帮我看看
1

Claude 会开始 Glob 扫目录、Grep 搜关键词、Read 读文件，一轮探索下来消耗 15000～25000 Token。

✅ 高效写法：

查看 src/auth/login.ts 第 45 行，JWT 验证里 exp 字段没检查，
加上过期时间校验，过期时抛 AuthExpiredError
1
2

Claude 只需要 Read 一次文件、Edit 一次代码，3000～5000 Token 搞定，节省 70%～80%。

万能提问公式：做什么 + 在哪个文件 + 具体改什么 + 用什么方式

技巧 4：用 .claudeignore 排除无关文件 ​

大模型按输入 Token 长度收费。让 Claude 读 node_modules、dist、.git 等文件夹是纯粹的浪费。

在项目根目录创建 .claudeignore 文件：

node_modules/
dist/
.git/
*.log
coverage/
.next/
1
2
3
4
5
6

实测可减少 25% 的输入 Token。

技巧 5：90% 的任务用 Sonnet，难题才用 Opus ​

场景推荐模型原因
日常功能开发、代码补全Sonnet能力已足够，价格低 5 倍
复杂架构设计、多文件重构Opus真正需要顶级推理时再用
简单格式化、文档生成Haiku极简任务，极低成本

切换命令：/model sonnet / /model opus / /model haiku

技巧 6：保持 CLAUDE.md 精简 ​

CLAUDE.md 会随每一条消息一起发送，文件越长，每次都多花 Token。

  • 只放最核心的规则（技术栈、编码规范、注意事项）
  • 不常用的规则移到 skill 文件，按需加载
  • 单个文件控制在 500 行以内

有位开发者测试：CLAUDE.md 从 200 行精简到 50 行后，日均 Token 消耗降低了约 15%。

技巧 7：利用 Prompt Caching 缓存重复内容 ​

当你在同一会话或短时间内发送包含相同上下文的请求时，API 会自动命中缓存：

  • 缓存读取价格 = 基础输入价格的 1/10
  • 缓存有效期：5 分钟内连续操作不失效

实用建议： 尽量集中连续完成相关任务，避免超过 5 分钟的闲置，否则缓存失效、下次重新计费。

完成任务就 /clear，对话变长就 /compact，问题写清楚别让 Claude 自己找——这三个习惯，立刻省下 50% 以上的 Token 消耗。
